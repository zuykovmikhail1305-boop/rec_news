# Backend: демо-вход и обзор компании

Веб получает существующие профили из ML API. Пользователь выбирает компанию и роль,
Backend проверяет профиль через `GET /profiles/{user_id}`, подписывает cookie и
открывает главную страницу с данными выбранной компании. Регистрации и паролей нет,
аккаунты или профили в БД не создаются. Это демо-выбор профиля, а не проверка личности.

## Запуск (PowerShell, Python 3.11+)

Из корня репозитория:

```powershell
cd services/backend
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
$env:ML_API_URL = 'http://127.0.0.1:8002'
.venv/Scripts/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000/. На Linux используйте `.venv/bin/python`.
ML-сервис запускается отдельно на порту 8002 согласно `services/ml/docs/api.md`.
`services/ml/scripts/init_db.py` — отдельная подготовка инфраструктуры ML,
Backend его не запускает. Профили должны уже существовать в БД ML.
Если ML недоступен, экран входа показывает ошибку с повторной загрузкой.
Если профилей нет, показывается пустой список без подстановки вымышленных аккаунтов.

## Настройки

- `ML_API_URL`: по умолчанию `http://127.0.0.1:8002`.
- `SECRET_KEY`: секрет подписи. Задайте стабильное случайное значение, чтобы вход
  сохранялся между перезапусками и несколькими API-процессами. Без настройки
  создаётся случайный ключ на процесс; перезапуск потребует повторного входа.
- `ENV=prod`: ставит Secure-флаг cookie, требует HTTPS.

Cookie `demo_session`: HttpOnly, SameSite=Lax, срок 14 дней. Внутри только выбранный
`user_id`, данные профиля каждый раз читаются из ML API. Подпись и срок проверяются
на сервере. POST входа/выхода защищён отдельным подписанным CSRF-токеном.
При временной ошибке ML выбор сохраняется, при удалении профиля cookie очищается.
Страницы с данными профиля возвращают `Cache-Control: no-store`.

## Маршруты

- `GET /login` — список существующих профилей (по 50, `offset` для пагинации).
- `POST /login` — выбрать `user_id`, проверить его в ML и войти.
- `GET /` — защищённый обзор компании, контекст и состояние готовых материалов.
- `GET /login?switch=true` — выбрать другой профиль.
- `POST /logout` — очистить cookie и вернуться к выбору.
- Старые `/insights` и `/insights/prototype` перенаправляются на актуальную страницу.

Список использует `GET /profiles?limit=50&offset=...`; главная и вход —
`GET /profiles/{user_id}`. ML является внутренним сервисом, браузер обращается
только к Backend. Веб не импортирует ML-модули и не открывает его SQLite-базы.
Главная показывает сведения из профиля, `company_facts`, `interests` и `activity`.
Получение содержимого ленты, карточек инсайтов и чата — отдельный следующий этап.
Старые файлы прототипа сохранены как исходные материалы, их JS с тестовыми
пользователями и демонстрационным входом на новой странице не подключается.

## Проверка

Из `services/backend`:

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
```

Тесты используют изолированный ML-клиент: выбор/смена профиля, сохранение входа,
выход, подделанная и истёкшая cookie, CSRF, удалённый профиль, недоступность ML,
пустой список, пагинация, HTML-экранирование и соответствие контракту ML.
