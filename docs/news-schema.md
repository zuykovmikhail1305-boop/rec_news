# Схема хранения HTML-публикаций

Первый реализованный этап парсера: модели SQLAlchemy `NewsSource`, `NewsRaw`
и `NewsQuote` в `app/models.py`. Пользователи и анкеты остаются в своих таблицах.
Сбор страниц, расписание и LLM-обогащение пока не реализованы.

## Создание таблиц

В окружении с установленными зависимостями проекта, из корня репозитория:

```sh
cd app
python init_news_db.py
```

Используется существующий `DATABASE_URL`, по умолчанию `./alfa.db` относительно рабочей директории.
Для отдельной локальной базы:

```sh
DATABASE_URL=sqlite:////tmp/news-parser.sqlite python init_news_db.py
```

Команда создаёт только три новые таблицы и их индексы, не удаляет существующие
данные; повторный запуск допустим. При обычном запуске веб-приложения они также
создаются существующим `Base.metadata.create_all`. Это добавление таблиц,
а не система миграций: последующие изменения уже созданных колонок потребуют
отдельной миграции. SQLite включает проверку внешних ключей на каждом соединении.

## Таблицы

- `news_sources`: `id`, уникальный `code`, `name`, `base_url`, `listing_url`,
  `parser_key`, `enabled` (по умолчанию true), `last_success_at`.
- `news_raw`: `id`, `source_id`, `url`, `title`, `raw_html`, `text`,
  `published_at`, `discovered_at`, `fetched_at`, `content_hash`, `status`,
  `attempt_count`, `next_retry_at`, `processing_started_at`, `last_error`,
  `parser_version`.
- `news_quotes`: `id`, `raw_id`, `quote_text`, `start_char`, `end_char`,
  `text_hash`, `created_at`.

Связи: `news_sources.id → news_raw.source_id`, `news_raw.id → news_quotes.raw_id`.
Удаление источника с публикациями или публикации с цитатами не каскадируется:
внешние ключи защищают сохранённые доказательства. Источник можно отключить
через `enabled`.

Публикация уникальна по `(source_id, url)`. URL нормализует будущий адаптер перед
сохранением. `content_hash` — SHA-256 точного `text`, закодированного в UTF-8;
индекс не уникален, чтобы сохранять одинаковые тексты разных публикаций.
Есть индекс `(status, next_retry_at)` для выбора очереди.

Ссылка создаётся со статусом `pending`, пустыми текстом/HTML и нулём попыток.
Допустимые состояния: `pending`, `processing`, `ready`, `retry`, `failed`.
Переходы, блокировка задач и повторные попытки — ответственность будущего воркера.
`ready` означает готовый извлечённый материал, а не готовый инсайт.

Даты адаптер передаёт в UTC с часовым поясом. PostgreSQL хранит timezone-aware
даты; SQLite не сохраняет информацию о часовом поясе: прочитанные наивные
значения следует интерпретировать как UTC. Серверные даты SQLite создаются в UTC.

## Цитаты

Создавать через `create_quote` из `app/news_quotes.py`, затем добавлять результат
в текущую SQLAlchemy-сессию. Функция проверяет:

```python
raw.text[start_char:end_char] == quote_text
```

Позиции — индексы символов Python (Unicode code points), начало включительно,
конец исключительно; это не байты и не индексы UTF-16 JavaScript.
Хеш всего текста вычисляется функцией, а не берётся на доверии из `content_hash`.
Ограничения БД дополнительно проверяют диапазон и длину цитаты; соответствие
содержимому другой таблицы проверяется именно функцией, не SQL CHECK.

При отображении/использовании цитаты после изменения статьи вызывайте
`quote_matches_text(quote, raw.text)`: изменённый текст делает старую цитату
невалидной, даже если цитируемые слова ещё встречаются. После перепарсинга
цитаты необходимо извлечь и проверить повторно. История версий текста пока
не хранится. HTML-парсер сам не выбирает доказательства будущего AI-вывода.

## Проверка

Из корня, с установленным SQLAlchemy из зависимостей проекта:

```sh
python -m unittest discover -s tests -p 'test_news_schema.py' -v
```

Тесты работают в отдельной SQLite-базе в памяти. Проверяют сохранность
существующих пользователей, повторную инициализацию, уникальность URL,
неуникальность хеша, ограничения БД, цитаты и компиляцию DDL PostgreSQL.
Последняя проверка не заменяет интеграционный тест на сервере PostgreSQL.
