# HTML-парсер ТАСС: первый эксперимент

Стек: `httpx` загружает HTML, `selectolax` собирает ссылки,
`Trafilatura` выделяет основной текст. JSON-LD / OpenGraph / h1 уточняют заголовок,
JSON-LD / OpenGraph — время публикации. JavaScript и LLM не запускаются.

## Что проверено

22 октября 2026 года запрос `https://tass.ru/ekonomika` из рабочей среды получил
HTTP 403 с HTML защиты от ботов. **Успешного сбора реальных статей пока нет**:
структура ссылок и качество выделения текста на актуальной разметке ТАСС требуют
проверки из среды, где сайт доступен. Переключения IP, обхода защиты или подмены
браузера нет. Синтетические HTML в `tests/fixtures` проверяют алгоритмы и запись
в БД, но не являются копиями страниц ТАСС или подтверждением совместимости.

## Установка и запуск

Из корня репозитория, Python 3.12:

```sh
python -m venv .venv
.venv/bin/pip install -r requirements-parser.txt
DATABASE_URL=sqlite:////tmp/tass-news.sqlite .venv/bin/python app/tass_parser.py --limit 5
```

Веб-приложение и его зависимости для этой команды не нужны. Без `DATABASE_URL`
используется настройка проекта (`./alfa.db` относительно текущей директории).
Команда создаёт три таблицы новостей и запись источника `tass`, но не меняет
структуру таблиц пользователей. Настройки схемы: [news-schema.md](news-schema.md).

Команда обрабатывает до пяти новых/доступных для повторной попытки статей
(максимум `--limit 20`). Ссылки выбираются в порядке появления в HTML,
хронологическая сортировка и пагинация пока не реализованы. Находит только
HTML-ссылки вида `https://tass.ru/<section>/<id>`. Параметры и фрагменты URL
удаляются, повторные ссылки объединяются. Присутствие ссылки в HTML раздела
не гарантирует тематическую принадлежность к экономике: LLM-фильтрации нет.

Между сетевыми запросами минимум 5 секунд, таймаут 30 секунд. Редиректы разрешены
только на HTTPS доменов `tass.ru` / `www.tass.ru`. HTTP 403/429 останавливают прогон.
Ошибки 429/5xx и сетевые сбои сохраняются как `retry`; следующая попытка через
15/30 минут, максимум три попытки. Повтор происходит при следующем ручном запуске,
автоматического планировщика нет. Ошибки извлечения и постоянные HTTP-ошибки
получают `failed`; такие записи автоматически не перезапускаются.

Успешные публикации получают `ready`, оригинальный HTML, очищенный текст,
заголовок, SHA-256, время загрузки и версию парсера. `published_at` заполняется
только при наличии ISO-времени с часовым поясом; иначе остаётся NULL.
Цитаты и инсайты автоматически не создаются. Статьи `ready` не перезагружаются;
обнаружение обновлений публикаций — следующий этап.

На stdout выводится JSON счётчиков, ошибки — на stderr. Код выхода 1 означает
ошибку/отложенную обработку; отказ загрузки страницы раздела также завершает
команду с кодом 1. Если ссылок не найдено, это ошибка, а не успешный пустой прогон.
`discovered` — число уникальных ссылок в HTML, а не число записанных статей.

Запускайте один экземпляр команды: конкурентный захват задач пока не реализован.
Записи `processing`, оставшиеся после сбоя более 15 минут назад, могут быть
подхвачены следующим ручным запуском.

## Проверка без доступа к сайту

Сохранённую статью можно загрузить без сети:

```sh
DATABASE_URL=sqlite:////tmp/tass-local.sqlite .venv/bin/python app/tass_parser.py \
  --html /path/to/article.html --url https://tass.ru/ekonomika/ARTICLE_ID
```

Вместо ARTICLE_ID нужен числовой ID исходной статьи. Для синтетической проверки
используйте отдельную базу и прилагаемый вымышленный материал:

```sh
DATABASE_URL=sqlite:////tmp/tass-fixture.sqlite .venv/bin/python app/tass_parser.py \
  --html tests/fixtures/tass_article.html --url https://tass.ru/ekonomika/999000001
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

Не смешивайте синтетическую проверку с базой реальных публикаций. Для следующего
шага нужны сохранённый HTML реальной страницы раздела и нескольких статей либо
успешный запуск из другой среды; после этого можно уточнить селекторы и сравнить
извлечённый текст с оригиналом вручную.
